# 計算エンジンの仕様

`app/engine.js` の `compute(state)` が、入力から年ごとのキャッシュフロー表を作る。
Excel「ライフプラン表 ver.1.79」の CF表シートの数式を、行ごとに対応させて実装している。
金額の単位は万円、率は％で受け取る。

## 期間

開始年から、家族１の年齢（その年 − 生年）が終了年齢に達する年までの各年。
サンプル（家族１が1991年生まれ、90歳まで）では 2026〜2081年の56年。

## 行の型

入力の行は4つの型のどれかで、その年の金額の出し方が決まっている。

| 型 | その年の金額 | 使っている項目 |
|---|---|---|
| 変更型 | その年以前で一番新しい行の金額 | 住宅費、保険料、自動車の維持費、公的年金、その他の経常支出 |
| 一時型 | その年の行の金額 | 退職一時金・その他一時収入、住宅費一時金、その他の一時支出 |
| 期間型 | 開始年〜終了年に入る行の年額 | 企業年金、個人年金・保険、投資の積立、投資の現金化 |
| 周期型 | 開始年から N 年ごと、家族１が指定年齢になるまで | 自動車の購入費 |

給与と基本生活費は変更型に上昇率が付いた特別な型（下記）。

## 各行の計算（CF表シートとの対応）

| CF表の行 | 計算 |
|---|---|
| 11〜13 給与 | 開始年は1行目の金額。変更年は その行の金額 ×（1＋その行の上昇率）^（その年 − 開始年）。それ以外は 前年 ×（1＋直近の変更行の上昇率）。退職年齢に達した年から0 |
| 14 退職金・年金・その他 | 一時収入＋企業年金＋個人年金＋公的年金 |
| 15〜16 投資の現金化 | 予定額が前年末のその資産の残高以下ならその額、超えるならその年は0 |
| 19 基本生活費 | 開始年は1行目の金額。変更年は 入力額 ×（1＋物価上昇率）^（その年 − 開始年）。それ以外は 前年 ×（1＋物価上昇率） |
| 20 住宅費 | 変更型（1行目は開始年から）＋一時金 |
| 21 教育費 | 子供ごとに、在学期間に入る段の年額の合計 |
| 22 保険料 | 変更型 |
| 23 自動車 | 維持費（変更型。家族１が購入費の「◯歳まで」を過ぎた年から0）＋購入費（周期型） |
| 24 その他 | 経常支出（変更型）＋一時支出 |
| 25〜26 投資の積立 | 予定額が「前年末の普通預金 − その年すでに積み立てた額」以下ならその額、超えるならその年は0 |
| 28 年間収支 | 収入計 − 支出計（現金化は収入、積立は支出に含む） |
| 31 普通預金等 | （前年末 ＋ 年間収支）×（1 ＋ 利率 × 0.8） |
| 32〜33 投資資産 | （前年末 − 現金化）×（1 ＋ 想定利回り ×（1 − 税率））＋ 積立 |

教育費の在学年は生年月日から決まる。4月1日以前生まれ（早生まれ）は1年早い。
各段の金額は単価表（`EDU_UNIT`、入力シート T138:V153 と同じ）から引く。

## Excelでの確認状況

`npm test` で照合している。差が50円（0.005万円）を超えたら不一致。

| 照合 | 内容 | 結果 |
|---|---|---|
| サンプル入力 | Excelが保存した計算済みの値（56年×20項目） | 一致（最大差 2×10⁻¹¹ 万円） |
| シナリオ1 | 上昇率付きの給与変更、3人目の収入、遅生まれ・早生まれの子、私立、教育費と車の上書き、個人年金・企業年金、税率20%、預金利率 | 一致 |
| シナリオ2 | 預金不足で積立が止まる、残高不足で現金化が止まる | 一致 |
| シナリオ3 | 開始年2030、子供なし、95歳まで、維持費の打ち切り | 一致 |

シナリオは `test/scenarios/*.json` の入力をExcelに流し込み、LibreOfficeで再計算して作る。
LibreOfficeは給与の数式の `MAX(INDEX(配列,0))` だけ計算できないので、作業用のコピーでだけ同じ意味の
`SUMPRODUCT(MAX(配列))` に置き換える。置き換えたうえでサンプル入力がExcelの保存値と一致することを毎回確かめてから使う。

```
python3 -I tools/extract_excel_fixture.py <ライフプラン表.xlsx>   # サンプルの値 → test/fixtures/excel-cf.json
python3 -I tools/excel_scenarios.py <ライフプラン表.xlsx>         # シナリオ → test/fixtures/scenario-*.json
npm test
```

Excel本体は公開リポジトリに入れない（`.gitignore` 済み）。リポジトリにあるのは入力と計算結果の数値だけ。
シナリオの照合で実際に見つかったずれ：給与の変更年に上昇率を掛けていなかった（サンプルでは2行目の上昇率が0%のため見えなかった）。

## Excelと挙動を変えたところ

Excelの入力ルール（注意書き）を守った入力なら、どれもExcelと同じ結果になる。違うのは、ルールを外れた入力をしたときだけ。

1. **同じ年の変更行は合算する。** Excelは先頭の1行だけを拾う（注意書きで「同じ年は1行にまとめる」よう求めている）。アプリは合算したうえで、重複を知らせて1行にまとめるボタンを出す。
2. **期間型の行の間に空白の年があれば、その年は0。** Excelは前の行の金額を引き継ぐ（注意書きで「空白期間は0万円の行を入れる」よう求めている）。アプリは「＋」で足す行が前の行の翌年から始まるので、普通は空白ができない。
3. **期間型の行が重なった年は合算する。** Excelは後から始まった行の金額だけを使う。
4. **期間型の行が開始年より前から始まっていても、その金額を使う。** Excelは開始年の時点で始まる行が見つからないと、その期間を0にする。
5. **「◯歳まで働く」は、その年齢に達した年から給与を0にする。** Excelでは利用者が「0の行」を入れる。サンプルの家族１は「生年＋65年」に0の行があり、これと同じ結果になる。

## 画面の作りで決めたこと

- 給与・基本生活費・住宅費の1行目の年は「開始年」に固定し、変えられないようにした。Excelは1行目の年を見ずに開始年から使うため、変えられると誤解を招く。
- 普通預金等の利率を入力できるようにした。Excelでは入力シートになく、CF表シートの C31 に直接置かれている（0）。初期値は0。
- 教育費の在学年を書き換えた段は、生年月日を後から変えても動かない。書き換えていない段は生年月日に追従する。
- 自動車の購入費を回ごとに変えた金額は年で覚えている。開始年や周期を変えて、その年が購入年でなくなった場合、その上書きは使われない。
- 手取額計算の課税所得は万円未満を切り捨てる（シートの課税所得 270・272 と合わせるため）。
