# 計算エンジンの仕様

`app/engine.js` の `compute(state)` が、入力から年ごとのキャッシュフロー表を作る。
Excel「ライフプラン表 ver.1.79」の CF表シートの数式を、行ごとに対応させて実装している。
金額の単位は万円、率は％で受け取る。

## 期間

開始年から、家族１の年齢（その年 − 生年）が終了年齢に達する年までの各年。
サンプル（家族１が1991年生まれ、90歳まで）では 2026〜2081年の56年。

## 行の型

入力の行は4つの型のどれかで、その年の金額の出し方が決まっている。

| 型 | その年の金額 | 使っている項目 |
|---|---|---|
| 変更型 | その年以前で一番新しい行の金額 | 住宅費、保険料、自動車の維持費、公的年金、その他の経常支出 |
| 一時型 | その年の行の金額 | 退職一時金・その他一時収入、住宅費一時金、その他の一時支出 |
| 期間型 | 開始年〜終了年に入る行の年額 | 企業年金、個人年金・保険、投資の積立、投資の現金化 |
| 周期型 | 開始年から N 年ごと、家族１が指定年齢になるまで | 自動車の購入費 |

給与と基本生活費は変更型に上昇率が付いた特別な型（下記）。

## 各行の計算（CF表シートとの対応）

| CF表の行 | 計算 |
|---|---|
| 11〜13 給与 | 開始年は1行目の金額。変更年は その行の金額 ×（1＋その行の上昇率）^（その年 − 開始年）。それ以外は 前年 ×（1＋直近の変更行の上昇率）。退職年齢に達した年から0 |
| 14 退職金・年金・その他 | 一時収入＋企業年金＋個人年金＋公的年金 |
| 15〜16 投資の現金化 | 予定額が前年末のその資産の残高以下ならその額、超えるならその年は0 |
| 19 基本生活費 | 開始年は1行目の金額。変更年は 入力額 ×（1＋物価上昇率）^（その年 − 開始年）。それ以外は 前年 ×（1＋物価上昇率） |
| 20 住宅費 | 変更型（1行目は開始年から）＋一時金 |
| 21 教育費 | 子供ごとに、在学期間に入る段の年額の合計 |
| 22 保険料 | 変更型 |
| 23 自動車 | 維持費（変更型。家族１が購入費の「◯歳まで」を過ぎた年から0）＋購入費（周期型） |
| 24 その他 | 経常支出（変更型）＋一時支出 |
| 25〜26 投資の積立 | 予定額が「前年末の普通預金 − その年すでに積み立てた額」以下ならその額、超えるならその年は0 |
| 28 年間収支 | 収入計 − 支出計（現金化は収入、積立は支出に含む） |
| 31 普通預金等 | （前年末 ＋ 年間収支）×（1 ＋ 利率 × 0.8） |
| 32〜33 投資資産 | （前年末 − 現金化）×（1 ＋ 想定利回り ×（1 − 税率））＋ 積立 |

教育費の在学年は生年月日から決まる。4月1日以前生まれ（早生まれ）は1年早い。
各段の金額は単価表（`EDU_UNIT`、入力シート T138:V153 と同じ）から引く。

## Excelでの確認状況

`npm test` で照合している。差が50円（0.005万円）を超えたら不一致。

| 照合 | 内容 | 結果 |
|---|---|---|
| サンプル入力 | Excelが保存した計算済みの値（56年×20項目） | 一致（最大差 2×10⁻¹¹ 万円） |
| シナリオ1 | 上昇率付きの給与変更、3人目の収入、遅生まれ・早生まれの子、私立、教育費と車の上書き、個人年金・企業年金、税率20%、預金利率 | 一致 |
| シナリオ2 | 預金不足で積立が止まる、残高不足で現金化が止まる | 一致 |
| シナリオ3 | 開始年2030、子供なし、95歳まで、維持費の打ち切り | 一致 |

シナリオは `test/scenarios/*.json` の入力をExcelに流し込み、LibreOfficeで再計算して作る。
LibreOfficeは給与の数式の `MAX(INDEX(配列,0))` だけ計算できないので、作業用のコピーでだけ同じ意味の
`SUMPRODUCT(MAX(配列))` に置き換える。置き換えたうえでサンプル入力がExcelの保存値と一致することを毎回確かめてから使う。

```
python3 -I tools/extract_excel_fixture.py <ライフプラン表.xlsx>   # サンプルの値 → test/fixtures/excel-cf.json
python3 -I tools/excel_scenarios.py <ライフプラン表.xlsx>         # シナリオ → test/fixtures/scenario-*.json
npm test
```

Excel本体は公開リポジトリに入れない（`.gitignore` 済み）。リポジトリにあるのは入力と計算結果の数値だけ。
シナリオの照合で実際に見つかったずれ：給与の変更年に上昇率を掛けていなかった（サンプルでは2行目の上昇率が0%のため見えなかった）。

## Excelと挙動を変えたところ

Excelの入力ルール（注意書き）を守った入力なら、どれもExcelと同じ結果になる。違うのは、ルールを外れた入力をしたときだけ。

1. **同じ年の変更行は合算する。** Excelは先頭の1行だけを拾う（注意書きで「同じ年は1行にまとめる」よう求めている）。アプリは合算したうえで、重複を知らせて1行にまとめるボタンを出す。
2. **期間型の行の間に空白の年があれば、その年は0。** Excelは前の行の金額を引き継ぐ（注意書きで「空白期間は0万円の行を入れる」よう求めている）。アプリは「＋」で足す行が前の行の翌年から始まるので、普通は空白ができない。
3. **期間型の行が重なった年は合算する。** Excelは後から始まった行の金額だけを使う。
4. **期間型の行が開始年より前から始まっていても、その金額を使う。** Excelは開始年の時点で始まる行が見つからないと、その期間を0にする。
5. **「◯歳まで働く」は、その年齢に達した年から給与を0にする。** Excelでは利用者が「0の行」を入れる。サンプルの家族１は「生年＋65年」に0の行があり、これと同じ結果になる。

## 公的年金の試算（`pensionEstimate`、入力シート T85:AL91）

受け取る公的年金額がわからないときの、おおざっぱな理論値。家族１・家族２それぞれについて：

```
報酬比例 ＝ ROUND（（入社時の手取額 ＋ 最終退職時の手取額）÷ 2 × （最終退職年 − 入社年 ＋ 1）× 0.55%, 0）
年金額   ＝（報酬比例 ＋ 基礎年金）× 調整
```

初期値はExcelと同じで、入社＝生年＋22年、最終退職＝入社＋38年、基礎年金70万円、調整90％（所得代替率の低下を見込む）。
サンプル（入社2013年・最終退職2051年、手取り300→700万円と300→400万円）で 159.3 ＋ 130.5 ＝ 289.8万円となり、Excelの AK87・AK89・AK91 と一致する。
試算の入力は `state.penCalc` に置き、CF表の計算には使わない。「反映する」を押すと合計が公的年金の1行目に入る。

## 住宅ローンの試算（`loanSchedule`、入力シート T114:AH125・住宅ローン返済表シート）

元利均等返済を月ごとに計算する（返済表シートの PPMT・IPMT と同じ）。金利は3段階まで変えられる。

- 各段階の月返済額は「その段階のはじめの残高」を「完済までの残り回数」と「その段階の金利」で割り戻した額。
  2段階目以降のはじめの残高は、前の段階の表で年数×12回払った後の残高（返済表シートの B432・B860）。
- 最後の段階の年数は、返済期間の残り全部とする（Excelは入力する。返済期間と合わないと0円の年ができるため）。
- 修繕・管理費、固定資産税は1つの年額にした（Excelは段階ごとに入力できるが、サンプルはすべて同じ50万円）。

サンプル（2027年から4500万円・35年、当初1%を10年、その後2%）で、年間返済額 152.43 → 171.44万円、
返済総額 5,810.27万円、10年後の残高 3,370.6万円となり、Excelの X118・AB118・AE119 と返済表の E126 に一致する。

「住宅費に反映する」は、借入開始年以降の住宅費の行を、各段階の「返済＋修繕・管理費等」と完済後の「修繕・管理費等」の行に置き換える
（Excelの T125:AI125 と同じ並び）。置き換わる行があれば先に確かめる。借入開始が開始年以前なら、開始年時点の額を1行目に入れる。
試算の入力は `state.loanCalc` に置き、CF表の計算には使わない。

## 入力の確認（`validate(state)`）

計算はどんな入力でも止まらずに行う。そのうえで、計算に使われない入力や結果がおかしくなる入力を
`{ at, field, level, msg }` の一覧で返す。`at` は画面の場所（`start`、`fam:<id>`、`row:<項目>:<id>`、
`salrow:<給与>:<行>`、`inv:<資産>:<add|out>:<行>`、`edu:<子>:<段>` など）、`level` は
`error`（結果が正しくならない）か `warn`（計算はするが意図と違いそう）。

| 見つけるもの | level |
|---|---|
| 開始年が1990〜2100でない／家族１の生年月日が無い・日付でない・開始年より後 | error |
| 終了年齢が開始年の家族１の年齢以下、または120歳超（このときCF表の年が0になる） | error |
| 年が空の行、期間型の「まで」が無い・「から」より前、教育費の在学年の逆転、車の買い替え間隔が1年未満 | error |
| 一時型・期間型の行が計算期間の外、変更型の行が終了年より後 | warn |
| 給与・基本生活費・住宅費の2行目以降が開始年以前（Excelと同じく使われない） | warn |
| 開始年にはもう退職年齢を過ぎている、車の「◯歳まで」が初回購入より前 | warn |
| 率が±10％を超える（「1.5％」を「15」と入れた疑い）、マイナスの金額 | warn |
| 家族１が開始年に18歳未満 | warn |

## 画面の作りで決めたこと

- 給与・基本生活費・住宅費の1行目の年は「開始年」に固定し、変えられないようにした。Excelは1行目の年を見ずに開始年から使うため、変えられると誤解を招く。
- 普通預金等の利率を入力できるようにした。Excelでは入力シートになく、CF表シートの C31 に直接置かれている（0）。初期値は0。
- 教育費の在学年を書き換えた段は、生年月日を後から変えても動かない。書き換えていない段は生年月日に追従する。
- 自動車の購入費を回ごとに変えた金額は年で覚えている。開始年や周期を変えて、その年が購入年でなくなった場合、その上書きは使われない。
- 生年月日は端末の日付選択を使う。保存はExcelと同じ「1990/04/01」の形で、エンジンは「1990-04-01」も読める。
- 年の欄を年齢で入れる設定でも、保存は西暦。年齢の基準は家族１（給与はその人、教育費はその子）。

## 手取りの定義

このアプリの手取り（ライフプランの給与の欄に入れる額）は、

**手取り ＝ 額面 − 社会保険料 − 所得税 − 住民税 ＋ 通勤手当**

引くのは強制的に引かれるものだけ。自分で選んで給与から天引きしているもの（生命保険料・財形・持株会・DCの個人の上乗せ・社宅家賃・組合費など）は
手取りに含め、プランの支出や投資の欄に入れる。DCの会社拠出は手取りに入れず、退職金として入れる。
通勤手当は非課税で年収（源泉徴収票の支払金額）に入らないが、給与と一緒に振り込まれ、家計簿では交通費が支出に出るので足す。
手取りの計算では、どちらの出し方でも通勤手当（月額・円）×12 を最後に足す（画面側の `calcResult`）。

家計簿では、決済手段が「給与天引き」の支出を収入にも同じ額だけ足す（`deducted`）。収入（振込額）＋天引き＝上の手取りになり、
口座残高との照合はずれない。ライフプランへ反映するときは家族１の給与に含める。

## 給与明細（`app/book.js` の `paySummary` ほか、Excel ver.1.80「給与シート」）

家計簿の年ごとに、家族１・家族２の明細を14枚（1〜12月と夏・冬の賞与）持つ（`y.pay['1']`・`y.pay['2']`）。金額は円。

| 項目 | 計算 | Excel |
|---|---|---|
| 支給合計 | 基本給＋役職手当＋資格・職能手当＋残業手当＋その他手当＋その他支給＋通勤費 | K列 |
| 控除合計 | 健康保険＋介護保険＋厚生年金＋雇用保険＋所得税＋住民税＋財形・DC等 | K列 |
| 振込額 | 支給合計−控除合計 | L列 |
| 額面 | 支給合計−通勤費 | I44 |
| 手取り | 支給合計−社会保険料（健保・介護・厚年・雇用）−所得税−住民税 ＝ 振込額＋財形・DC等 | （I47に財形・DC等を足したもの） |
| 手取り率 | （手取り−通勤費）÷額面 | I49 |

Excelの★（I51、入力シートに入れる額）は振込額で、任意の天引き（財形・DC等）も引いている。アプリは上の「手取りの定義」に合わせて含める。
記入例は財形・DC等が0なので、1枚ごとの合計・振込額と、年間の支給・通勤費・額面・社会保険料・税・振込額・手取り率がExcelと一致する（`test/fixtures/excel-salary.json`、LibreOfficeで再計算した値）。
記録が12か月に満たないときは、記録した月の平均×12＋記録した賞与で1年分を見積もる。家計簿へは、その月の給与の振込額を「給与」、
支給月がその月の賞与の振込額を「ボーナス」の収入に、財形・DC等を決済手段「給与天引き」の支出に入れる。

## 投資シミュレーション（`investSim`・`investNeed`、Excel「投資シミュレーション」シート）

画面では「DC（会社拠出）の見込額」に使う。会社が出すDCの掛金は手取りに入れず、運用した結果を退職一時金として入れる。

| 年 | 投資結果 |
|---|---|
| 今年（開始年） | （前年末の残高＋積立額）×（1＋想定利回り−コスト） |
| 翌年から | 前年の結果×（1＋想定利回り−コスト）＋積立額（積み立てる年齢まで。それ以降は0） |

累積投資額＝前年末の残高＋積立額の合計、リターン＝（結果−累積）÷累積。
記入例（残高100万円、35歳、年36万円を65歳まで、5％、コスト0.2％）で50年後まで、LibreOfficeで再計算した値と一致（`test/fixtures/excel-investsim.json`）。
65歳で2,893.0万円（積立1,216万円）。

`investNeed` は目標額に届く毎年の積立額。結果は積立額の一次式なので、積立0と1で計算して逆算する。
受け取る年齢（60歳以上）の年に、見込額を「退職一時金・その他一時収入」の行（備考「DC（会社拠出）」）に入れる。税金（退職所得控除）は計算しない。

## 手取額の計算（`takeHome`、手取額計算シート「年収から手取り額を簡易計算（会社員向け）2025.4～」）

シートの式をそのまま移した。金額は万円。

| 項目 | 計算 |
|---|---|
| 給与所得控除 | 年収190万円以下は65。それ以上は 年収×率＋額（191〜:30%+8、361〜:20%+44、661〜:10%+110、851〜:195） |
| 社会保険料 | 年収×15.5％（上限180）。下の「Excelにない追加」を参照 |
| 基礎控除 | 所得金額で 95／88（133〜）／68（337〜）／63（490〜）／58（656〜）／48（2351〜）… |
| 配偶者控除・配偶者特別控除 | 扶養配偶者ありのとき、配偶者の所得（年収−給与所得控除）と本人の所得の表（シート K14:O24）から 38〜0 |
| 扶養控除 | 16歳以上の子供など38、19〜23歳63、70歳以上で別居48・同居58（人数×額） |
| その他 | 生命保険料控除（既定5）、iDeCo、その他の控除 |
| 所得税 | 課税所得×税率−速算控除 |
| 住民税 | 課税所得×10％＋1＋0.2−前年のふるさと納税 |
| 手取り | 年収−社会保険料−所得税−住民税 |

照合：記入例（年収600万円、扶養なし）で手取り461.55万円。ほかに8通り（配偶者の年収0・100・150・200万円、本人の所得が900万円超、
16歳以上・19〜23歳の子、70歳以上の親、iDeCo・ふるさと納税、年収180万円）をシートに入れてLibreOfficeで再計算し、
配偶者控除・扶養控除・課税所得・所得税・住民税・手取りがすべて一致（`test/fixtures/excel-takehome.json`）。

### Excelにない追加（どれも任意。指定しなければExcelと同じ）

実際の手取りとの差が大きくなりやすい2点を、選べるようにした。

- **社会保険料**（`health`・`age`）：協会けんぽ（`kyokai`）か健康保険組合（`kumiai`）を選ぶと、本人負担の率で見積もる。
  健康保険 5.0％（組合は平均的な4.2％）、介護保険 0.8％（40〜64歳）、雇用保険 0.55％、厚生年金 9.15％（標準報酬の上限に合わせて年収1,080万円まで）。
  たとえば協会けんぽ・40歳未満で14.7％、40歳以上で15.5％、組合・40歳未満で13.9％。
  源泉徴収票の「社会保険料等の金額」がわかれば `social` に入れると、見積もりより優先する。年齢は家族構成の生年月日から開始年の年末で出す。
- **去年の年収**（`lastIncome`）：住民税は前年の所得で決まり、6月から1年間引かれる。去年の年収を入れると、住民税だけを
  去年の年収で計算する（控除は今年と同じ。社会保険料は実額なら年収に比例、見積もりなら去年の年齢の率）。
  昇給などで今年の年収が高いと、Excelの式（今年の年収で住民税）より手取りが多くなる。

例：年収800万円、去年740万円、配偶者を扶養、iDeCo等24万円、健康保険組合・38歳 → 手取り624.28万円
（Excelの式のままだと610.75万円。差のうち約4.5万円が住民税の年ずれ、約9万円が社会保険料の率）。
復興特別所得税（所得税の2.1％）と住宅ローン控除は含まない。

### 源泉徴収票から（`takeHomeFromSlip`）

見積もりではなく、源泉徴収票の実際の金額から出す（円で受け取り、万円で返す）。

手取り ＝ 支払金額 −（社会保険料等の金額 − うち小規模企業共済等掛金）− 源泉徴収税額 − 住民税

- 所得税・社会保険料は実額なので、年の途中の昇給、健康保険組合の料率、介護保険料、住宅ローン控除、復興特別所得税も入る。
- 小規模企業共済等掛金（iDeCo・企業型DCの本人掛金）は貯蓄なので、手取りに含める（Excelの式でiDeCoを控除にだけ使うのと同じ扱い）。
- 住民税は源泉徴収票に無い。給与明細や住民税決定通知書の年額があればそれを使い、無ければ
  （給与所得控除後の金額 − 所得控除の額の合計額、千円未満切り捨て）×10％＋1＋0.2 で見積もる（手取額計算シートと同じ）。
  源泉徴収票は去年分なので、見積もった住民税は今年6月から引かれる額に当たる。
